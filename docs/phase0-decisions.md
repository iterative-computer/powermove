# Phase 0 — spike results and decisions

Evidence: `spikes/probe/results-{file,app,finder}.json` (Electron 44.0.0, Chromium per `meta`), fixtures in `spikes/fixtures/`. Each row is a go/no-go for the Electron platform layer (Phase 1).

| # | Question | Result | Decision |
|---|---|---|---|
| a | Video decode via `HTMLVideoElement` | H.264 (mp4/mov), HEVC 8-bit (mp4/mov), **HEVC-with-alpha** (alpha survives), VP8, VP9, AV1 all decode with correct pixels. **ProRes 422 and ProRes 4444 do not** (`DEMUXER_ERROR_NO_SUPPORTED_STREAMS` / 0×0 track). AAC/Opus/MP3/FLAC/WAV decode. `VideoDecoder`/`MediaSource` report support for avc1, hvc1/hev1, vp8/vp9, av01. | **Go.** ProRes is the one regression vs WKWebView: import must detect-and-warn on the `<video>` `error` event ("ProRes needs transcoding"), not the extension allowlist. VP9/AV1 fixtures read `[0,216,0]` — a limited/full color-range tagging artifact in the fixtures, not a decode fault. |
| b | WebGPU | Adapter + device + `copyExternalImageToTexture` OK in ~7 ms, all launch modes. | **Go.** Drop the per-gesture adapter warm-up workaround (`spatial.js:293-298`) in Phase 3b, verify once. |
| c | WebCodecs encode | VP9 (`vp09.00.31.08`) and VP8 encoders OK (30×1080p frames in ~86 ms); **Opus `AudioEncoder` OK** and supplies `decoderConfig.description`. **H.264 `avc1` encoding unsupported.** | **Go.** Export stays WebM (VP9+Opus) — now frame-exact with audio on every run (the MediaRecorder fallback becomes dead code). H.264/MP4 export is a post-parity feature (needs a muxer + platform encoder path). |
| d | Generated-script sandbox under CSP | **Chromium inherits the parent CSP into `about:srcdoc` frames.** With `script-src 'self' 'unsafe-eval'` (no `'unsafe-inline'`) the sandbox's inline bootstrap is blocked in both file and app modes. | **Go (B2).** Serve `host/sandbox.html` + `host/sandbox.js` from `app://` with their own CSP header (`script-src app://powermove/host/sandbox.js 'unsafe-eval'; worker-src blob:; connect-src 'none'`) inside `<iframe sandbox="allow-scripts">` — verified: answer 42, opaque origin, fetch blocked, parent unreachable. `'self'` also matches under the sandboxed origin. blob: frames and srcdoc inherit the parent policy and fail; a hash-allowlisted inline bootstrap works but couples the app CSP to the sandbox source, so it is rejected. ## Consequences folded into the plan

- Import: extension allowlist stays; add ProRes detection on decode error with a specific message. HEVC no longer a risk item.
- Export: WebM/VP9/Opus only; the Phase 1 gate's "export with audio bit-checked" now exercises a path WKWebView never ran.
- Fonts: `PM.Fonts.setSystemFamilies` is fed from renderer `queryLocalFonts()` at boot (permission granted main-side); web fallback list retained.
- Sandbox: served `host/sandbox.html` (see row d); the legacy `scripting.js` gets a branch that loads it when `window.powermove` exists.
- Panel pool: focus restoration is part of the re-parent attachment contract.
- Scaffold review fixes applied by the integrator: `vitest.config.ts` (legacy `tests/` excluded), dev URL gated on `app.isPackaged`, `web-contents-created` + `will-frame-navigate` + `will-redirect` guards, IPC sender derived from the event (`BrowserWindow.fromWebContents` + frame URL check), MIME table (`.mov .m4a .aac .flac .m4v .wasm .map`), CJS output pinned for main/preload, `app.setName('Powermove')`, `lib: ["ES2022"]` for the node tsconfig.

## Found while booting the legacy renderer under Electron

- `js/gl/compositor.js`: shader and precomp layers rendered into a scratch FBO and never restored the caller's framebuffer, so `drawContent` sampled the scratch texture while drawing into it (Chromium: `GL_INVALID_OPERATION … Feedback loop`). Fixed by tracking the bound FBO/texture units and restoring the target after nested rendering; pool/content texture creation now goes through the tracked binder. 0 GL errors after the fix.
- Panel re-parenting loses focus and (occasionally) the selection range: `portal.ts` must snapshot `activeElement` + `selectionStart/End/Direction` and restore them after every move (B2, probe i2).
