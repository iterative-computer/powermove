# S1 — sandboxed V8 architecture spike

Status: execution in progress. Runtime and performance gates are not yet approved.
This is a synthetic, standalone spike, not the production extension runtime.

## Build route and pins

Upstream rusty_v8 provides the `v8_enable_sandbox` Cargo feature; that feature
also enables `v8_enable_pointer_compression`. Its 152.2.0 release publishes plain
and pointer-compressed libraries, **no sandbox libraries or sandbox bindings**.
Pointer compression alone does not prove sandbox protection. The selected route
is therefore the upstream feature plus a source build on GitHub's macOS ARM runner.
This follows the simplest pinned sandbox-on route rule and the owner's CI-only
source-build decision. No V8 C++ build runs on the development Mac.

Primary evidence:

The isolated Cargo and npm lockfiles pin transitive dependencies. The source
build uses upstream's own locked dependencies; the consumer uses the spike lock.
The same crate version, feature definitions and generated bindings are required.

`.github/workflows/native-v8.yml` accepts manual dispatch and S1-branch pushes.
A job guard excludes all branches outside `feat/na-s1-*`, including main. It has
read-only repository permissions, no tag/release/package publication and uploads
only expiring workflow artifacts. Runner cleanup is guarded by
`RUNNER_ENVIRONMENT=github-hosted` and `uname -m=arm64`, followed by a 20-GiB
free-space check. The source tree is shallow checked out with pinned submodules;
Cargo/GN output can be cached under the explicit sandbox configuration key.

GN explicitly enables sandbox, pointer compression, shared compression cage and
external code space, with symbols disabled. The artifact includes the library,
matching `src_binding.rs`, `args.gn`, source/submodule/tool versions and SHA-256
checksums. CI checks GN flags and links a separate crates.io consumer. Its smoke
test calls the same native `v8__V8__IsSandboxEnabled` symbol that upstream's own
tests use. This is a pinned test symbol, not a stable runtime API.

## Reproduction

```sh
gh workflow run native-v8.yml --ref feat/na-s1-v8
gh run watch RUN_ID --exit-status
df -h /
# Stop if free disk is below 4 GiB.
gh run download RUN_ID \
  --name rusty-v8-152.2.0-sandbox-aarch64-apple-darwin \
  --dir /tmp/pm-s1-v8-artifact
export PM_S1_ARTIFACT=/tmp/pm-s1-v8-artifact
apps/native/spikes/s1/run.sh
```

The build script sources `engine/env.sh`, selects Rust 1.96.1 and uses only
`~/Developer/pm-target`. An isolated manifest points to the same Rust sources so
this lane does not edit other lanes' workspace lockfile. It requires the local
artifact and checks hashes. It rejects `V8_FROM_SOURCE`; the consumer's archive
and binding paths both point to CI output. Raw logs, binaries, downloaded V8,
generated JS, private inputs and screenshots stay outside tracked files.

## Probes and decision rules

- **Sandbox buffers:** use `ArrayBuffer::new_backing_store` with the isolate's
  default sandbox allocator. Rust fills a uniquely owned backing store before
  publishing it. The pointer is unchanged and JavaScript checks every byte of a
  1920×1080 RGBA payload. No external Vec/Box/raw host pointer is imported. Store
  IPC reads directly into a separate helper's sandbox backing store: one counted
  4,096-byte IPC copy, then JS validation.
- **Snapshots:** separate editor-cluster, extension, compiler, Store and fallback
  kind snapshots, 30 restores per kind. These are small synthetic bootstraps, not
  the completed production runtime bundles. Code-cache acceptance is tested in
  a fresh isolate. Its length-delimited SHA-256 key includes V8 version, snapshot,
  bundle and flags; V8's own cached-data version tag is also reported.
- **Watchdog:** the harness explicitly authorizes Stop on a real infinite JS
  loop, using a thread-safe termination handle. The owner unwinds scopes, drops
  context Globals, exits/disposes and recreates from its kind snapshot plus a
  storage value captured before the runaway task. A Promise verifies per-task
  microtask draining. A stale handle is harmless after disposal. Trusted product
  behavior remains Stop/Wait; the harness is not automatic trusted-code killing.
- **Parking:** test SharedIsolate/Locker through eight newly created OS threads.
  The first working handoff option releases idle owner threads. Sharing is unsafe
  at the conversion boundary: only Send-compatible owned state is attached, with
  no cppgc heap, Weak handles or pending finalizers. Each access holds one Locker;
  no V8 references cross unlock boundaries. Disposal acquires the final lock.
- **Reload/history:** 20 new extension generations carry `hot.data`, each holds a
  1-MiB typed array captured by an external undo closure. Every retained closure
  stays callable. History retirement drops 19 generations, while an export pin
  retains generation zero; retiring that pin disposes the last generation.
  Report V8 external bytes and process physical footprint independently.
- **Cluster reload:** fresh-isolate replacement cannot preserve `===` references
  to live services. Staged module replacement inside the same cluster is tested
  for identity, held old providers, stacked/buried disposal, failed activation,
  storage and staged operations. Select it only if recovery and <50-ms reload
  hold. Keep the C-MATRIX editor dependency closure together; do not introduce
  synchronous calls between isolate threads. Full facade/eval coverage stays open.
- **Activation effects:** a separate asynchronous synthetic host stages storage,
  operations, registrations, subscriptions, timers and UI until activation
  succeeds. Failure preserves old effects; success revokes old registrations
  while retained history remains callable. Network/file effects are represented
  by an irreversible audit log, not claimed as rolled-back real I/O.
- **Quotas:** a real near-heap-limit callback terminates a 16-MiB isolate, using one
  bounded 8-MiB emergency increment to unwind. The test runs in a subprocess.
  A host-buffer quota refuses an over-limit allocation before allocating; its
  reservations conservatively last until generation retirement. This is not a
  hard allocator limit on all JS-created ArrayBuffers. That enforcement remains
  open; untrusted code must remain in helpers.
- **Cage:** a 3-GiB admission ledger for retained generations reserves configured
  heap maxima and releases after isolate disposal. An over-budget reservation is
  rejected. Compiler and active cluster/extension maxima must enter the same
  production ledger; an illustrative configuration includes compiler and retained
  generations below 3 GiB, leaving 1 GiB for headroom/overheads. Helpers have
  independent cages. This is not a claim that V8's ~1-TiB virtual sandbox is RSS.
- **Store confinement/OOM:** initialize trusted runtime code, apply deny-default
  seatbelt before any extension JS, deny file read/write/network with EPERM or
  EACCES, retain only inherited-socket IPC and system-library/JIT necessities.
  An ordinary helper validates IPC pixels. A second helper exhausts a real V8
  heap with no quota callback; require SIGABRT and V8's fatal-OOM diagnostic.
  A live parent isolate must retain its state. Compare helper footprint with the
  ≤20-MB rest target. This does not implement Store globals/permissions/corpus.
- **Reconciler:** the same 999-button plus stateful-component workload uses real
  Preact/Preact Refresh and React/React Refresh, a synthetic native-tree adapter,
  40 synchronous 1,000-component commits with keyed movement/props/text/listeners,
  and a state value of 17 preserved through a component replacement. Six operation
  kinds are exercised. A provisional 4-ms commit ceiling uses the app's main-work
  envelope; the plan does not state a separate numeric 1,000-node ceiling.
  This measures JS reconciliation and adapter work, excluding Rust atomic
  validation, IPC, GPUI paint and presentation. Choose the smallest candidate
  passing this subset, timing and Refresh; the full held-out eval remains a gate.

## Signed JIT verification

`run.sh` ad-hoc signs the actual linked ARM binary with hardened runtime and only
`com.apple.security.cs.allow-jit`, verifies the signature and displays its
entitlements. `jit.js` warms a function, requests optimization and requires the
V8 optimization-status bit plus the correct value. The spike enables native test
syntax expressly for this diagnostic. This is not a production runtime flag.
Release signing/notarization and the final app/helper bundles remain separate
checks; neither was published by this lane.

## Measurements and verdict

Pending the CI artifact. Local conditions: Apple M5, macOS 27.2 (26B5086k), shared
machine, release Rust consumer. These are architecture diagnostics, not paired
quiet-window Electron comparisons or a supported-macOS matrix.

S5's V8 trusted-realm + remote-DOM fallback is still required. The sandboxed
runtime, per-kind bootstrap, code-cache path and native-tree adapter are reusable
foundations; this spike does not implement a complete DOM bridge, extract the
compat kernel or resolve S5's pixel/lifecycle failures. All v1–3 live synchronous
services remain together until complete facades or the fallback pass their gates.

Before P1 approval: actual S1 runtime results, complete Store globals/fallback,
real activation effects and kernel gesture sealing, hard JS external-memory
limits, production cage admission, native commit validation/paint, full eval,
S5 remote DOM and supported OS/signed-app validation must be accounted for.
