# S1 — sandboxed V8 architecture spike

**CI and signed ARM64 functional probes PASS. Overall S1 gate OPEN:** reconciler
timing straddles the provisional ceiling, and the integration items below remain unverified.
This is a synthetic, standalone spike, not the production extension runtime.

## Build route and pins

Upstream rusty_v8 provides the `v8_enable_sandbox` Cargo feature; that feature
also enables `v8_enable_pointer_compression`. Its 152.2.0 release publishes plain
and pointer-compressed libraries, **no sandbox libraries or sandbox bindings**.
Pointer compression alone does not prove sandbox protection. The selected route
is therefore the upstream feature plus a source build on GitHub's macOS ARM runner.
This follows the simplest pinned sandbox-on route rule and the owner's CI-only
source-build decision. No V8 C++ build runs on the development Mac.

Primary evidence:

- [Pinned feature definitions](https://github.com/denoland/rusty_v8/blob/2768994f664e8a6e3aba27503606c58339136e2a/Cargo.toml)
- [Upstream experimental-feature limitations](https://github.com/denoland/rusty_v8/blob/2768994f664e8a6e3aba27503606c58339136e2a/README.md#experimental-features)

The isolated Cargo and npm lockfiles pin transitive dependencies. The source
build uses upstream's own locked dependencies; the consumer uses the spike lock.
The same crate version, feature definitions and generated bindings are required.

`.github/workflows/native-v8.yml` accepts manual dispatch and S1-branch pushes.
A job guard excludes all branches outside `feat/na-s1-*`, including main. It has
read-only repository permissions, no tag/release/package publication and uploads
only expiring workflow artifacts. Runner cleanup is guarded by
`RUNNER_ENVIRONMENT=github-hosted` and `uname -m=arm64`, followed by a 20-GiB
free-space check. The source tree is shallow checked out with pinned submodules;
Cargo/GN output can be cached under the explicit sandbox configuration key.

GN explicitly enables sandbox, pointer compression, shared compression cage and
external code space, with symbols disabled. The artifact includes the library,
matching `src_binding.rs`, `args.gn`, source/submodule/tool versions and SHA-256
checksums. CI checks GN flags and links a separate crates.io consumer. Its smoke
test calls the same native `v8__V8__IsSandboxEnabled` symbol that upstream's own
tests use. This is a pinned test symbol, not a stable runtime API.

## Reproduction

```sh
gh workflow run native-v8.yml --ref feat/na-s1-v8
gh run watch RUN_ID --exit-status
df -h /
# Stop if free disk is below 4 GiB.
gh run download RUN_ID \
  --name rusty-v8-152.2.0-sandbox-aarch64-apple-darwin \
  --dir /tmp/pm-s1-v8-artifact
export PM_S1_ARTIFACT=/tmp/pm-s1-v8-artifact
apps/native/spikes/s1/run.sh
```

The build script sources `engine/env.sh`, selects Rust 1.96.1 and uses only
`~/Developer/pm-target`. An isolated manifest points to the same Rust sources so
this lane does not edit other lanes' workspace lockfile. It requires the local
artifact and checks hashes, with a 4-GiB free-space check before and throughout
compilation. On macOS 27, Rust 1.96's stripped proc macros fail to load with
`mis-aligned LINKEDIT string pool` ([upstream #157750](https://github.com/rust-lang/rust/issues/157750)).
The isolated release build override disables stripping for build-time dependencies.
This was confirmed by `dlopen` failure before the change and a successful signed
release build afterwards; kache is retained. The parent native workspace's release
profile needs its own integration check, outside S1's file ownership.

It rejects `V8_FROM_SOURCE`; the consumer's archive
and binding paths both point to CI output. Raw logs, binaries, downloaded V8,
generated JS, private inputs and screenshots stay outside tracked files.

## Probes and decision rules

- **Sandbox buffers:** use `ArrayBuffer::new_backing_store` with the isolate's
  default sandbox allocator. Rust fills a uniquely owned backing store before
  publishing it. The pointer is unchanged and JavaScript checks every byte of a
  1920×1080 RGBA payload. No external Vec/Box/raw host pointer is imported. Store
  IPC reads directly into a separate helper's sandbox backing store: one counted
  4,096-byte IPC copy, then JS validation.
- **Snapshots:** separate editor-cluster, extension, compiler, Store and fallback
  kind snapshots, 30 restores per kind. The five small kind bootstraps do not contain the completed production runtime.
  A separate **real Svelte compiler snapshot** embeds the pinned compiler bundle,
  restores 30 fresh isolates and compiles after each restore. Code-cache acceptance is tested in
  a fresh isolate. Its length-delimited SHA-256 key includes V8 version, snapshot,
  bundle and flags; V8's own cached-data version tag is also reported.
- **Watchdog:** the harness explicitly authorizes Stop on a real infinite JS
  loop, using a thread-safe termination handle. The owner unwinds scopes, drops
  context Globals, exits/disposes and recreates from its kind snapshot plus a
  storage value captured before the runaway task. A Promise verifies per-task
  microtask draining. A stale handle is harmless after disposal. Trusted product
  behavior remains Stop/Wait; the harness is not automatic trusted-code killing.
- **Parking:** test SharedIsolate/Locker through eight newly created OS threads.
  The first working handoff option releases idle owner threads. Sharing is unsafe
  at the conversion boundary: only Send-compatible owned state is attached, with
  no cppgc heap, Weak handles or pending finalizers. Each access holds one Locker;
  no V8 references cross unlock boundaries. Disposal acquires the final lock.
- **Reload/history:** five waves of 20 new extension generations (100 total) carry `hot.data`, each holds a
  1-MiB typed array captured by an external undo closure. Every retained closure
  stays callable. History retirement drops 18 generations, while the active generation and an
  export pin on generation zero remain alive. Retiring the export releases its
  old generation; closing the active generation releases the last isolate.
  Report V8 external bytes and process physical footprint independently.
- **Cluster reload:** this fixture keeps live held provider references and a
  registration stack in one isolate; replacing that isolate does not carry those
  objects into the new one. Staged module replacement inside the same cluster is tested
  for identity, held old providers, stacked/buried disposal, failed activation,
  storage and staged operations. Select it only if recovery and <50-ms reload
  hold. Keep the C-MATRIX editor dependency closure together; do not introduce
  synchronous calls between isolate threads. Full facade/eval coverage stays open.
- **Activation effects:** a separate asynchronous synthetic host stages storage,
  operations, registrations, subscriptions, timers and UI until activation
  succeeds. Failure preserves old effects; success revokes old registrations
  while retained history remains callable. JSON storage is deep copied; a nested
  mutation regression was reproduced and fixed. Real bounded loopback traffic and
  a temporary-file write survive failed activation and are verified by Rust, then
  cleaned up. Event/timer/UI tables are driven virtually; production host wiring
  and arbitrary module-global mutation rollback are not implemented.
- **Quotas:** a real near-heap-limit callback terminates a 16-MiB isolate, using one
  bounded 8-MiB emergency increment to unwind. The test runs in a subprocess.
  A host-buffer quota refuses an over-limit allocation before allocating; its
  reservations conservatively last until generation retirement. This is not a
  hard allocator limit on all JS-created ArrayBuffers. A separate post-task
  external-memory check terminates a task that leaves 3 MiB under a 2-MiB policy.
  Hard enforcement during a runaway allocation remains
  open; untrusted code must remain in helpers.
- **Cage:** a 3-GiB admission ledger for retained generations reserves configured
  heap maxima and releases after isolate disposal. An over-budget reservation is
  rejected. Compiler and active cluster/extension maxima must enter the same
  production ledger; an illustrative configuration includes compiler and retained
  generations below 3 GiB, leaving 1 GiB for headroom/overheads. Helpers have
  independent cages. This is not a claim that V8's ~1-TiB virtual sandbox is RSS.
- **Store confinement/OOM:** initialize trusted runtime code, apply deny-default
  seatbelt before any extension JS, deny file read/write/network with EPERM or
  EACCES, retain only inherited-socket IPC and system-library/JIT necessities.
  An ordinary helper validates IPC pixels. A second helper exhausts a real V8
  heap with no quota callback; require SIGABRT or SIGTRAP plus V8's fatal-OOM diagnostic.
  A live parent isolate must retain its state. Compare helper footprint with the
  ≤20-MB rest target. This does not implement Store globals/permissions/corpus.
- **Reconciler:** the same 999-button plus stateful-component workload uses real
  Preact/Preact Refresh and React/React Refresh, a synthetic native-tree adapter,
  10 warmups plus 30 timed 1,000-widget commits (2,002 native nodes) with keyed movement/props/text/listeners,
  and a state value of 17 preserved through a component replacement. Six operation
  kinds are exercised. A provisional 4-ms commit ceiling uses the app's main-work
  envelope; the plan does not state a separate numeric 1,000-node ceiling.
  This measures JS reconciliation and adapter work, excluding Rust atomic
  validation, IPC, GPUI paint and presentation. Choose the smallest candidate
  passing this subset, timing and Refresh; the full held-out eval remains a gate.

## Signed JIT verification

`run.sh` ad-hoc signs the actual linked ARM binary with hardened runtime and only
`com.apple.security.cs.allow-jit`, verifies the signature and displays its
entitlements. `jit.js` warms a function, requests optimization and requires the
pinned V8 `kOptimized` (8) and `kTurboFanned` (32) bits plus the correct value.
Observed status **41**, signature verification PASS. The older bit-16 test was
corrected from the pinned [V8 enum](https://github.com/v8/v8/blob/c4ca1eccb90c5464d826b7713dc27178a53b0cfe/src/runtime/runtime.h#L1131). The spike enables native test
syntax expressly for this diagnostic. This is not a production runtime flag.
Release signing/notarization and the final app/helper bundles remain separate
checks; neither was published by this lane.

## Measurements and verdict

Final functional run exited **0** on Apple M5, macOS **27.2 (26B5086k)**, Rust
release build with hardened runtime and only allow-jit. All functional assertions
passed. Timings below come from a shared machine and development JS fixtures;
no quiet-window, paired Electron or supported-OS performance approval is claimed.
Functional success does **not** turn a failed timing row into a passing gate.

### Retained generations and release

Each wave retains 20 MiB of V8-reported external buffers. History closures remain
callable after reload, export retains old generation zero, and active generation
19 remains callable after history/export retirement. Every wave disposes all
20 isolates when the active generation closes; cage reservations go from
**1,280 MiB to 128 MiB to 64 MiB to zero**. The compiler-inclusive example reserves
2,336 MiB under the 3-GiB admission ceiling. Store cages are separate.

Approximately **26.66 MB** returns between holding all generations and closing

Logical disposal and substantial reclamation pass; a long production-bundle soak
and allocator-level attribution remain open. Do not call the residual memory zero
or claim this short run proves there are no leaks.

### Reconciler comparison and decision

Both real Refresh implementations preserved state **17**, including subsequent
commits. Both produced all six operation classes and the expected 2,002-node tree.
Operation traces are retained by the fixture and contribute to its reported heap.
The table includes two full signed runs of the same reconciler bundles, with 30
measured commits after 10 warmups in each run; these are development builds.

| React 19.3.1 + reconciler + Refresh | **705,706** | 1.810 / 2.936 | 3.916 / **5.657** | PASS |

**Neither is approved against a stable 4-ms ceiling.** Both pass in one diagnostic
run and fail in another. The numeric ceiling is provisional, derived from the
main-work envelope; JS reconciliation is off-main in the proposed app, and the
actual atomic native commit/paint path is not measured here. No threshold is
silently relaxed. Production-mode and quiet-window measurements plus the intended
eval subset must resolve selection. **Preact is the provisional size candidate**
(about 22× smaller here), not a frozen reconciler choice.

### Decisions and remaining gate

| Decision | Rule and evidence |
| --- | --- |
| CI source build using upstream sandbox feature | Simplest pinned sandbox+pointer-compressed route; no upstream sandbox assets; native runtime check PASS |
| Use sandbox backing stores; one Store IPC copy | Allocator ownership rule; pointer/data checks PASS |
| Release idle threads with SharedIsolate/Locker | First handoff option works across eight owner threads; no sleeping-thread fallback needed in this fixture |
| Stage replacement inside a live service cluster | Held objects/stack remain in one isolate, failed activation recovers, measured p95 well below 50 ms; full cluster semantics/eval still open |
| Co-locate live services; data-only complete facades | C-MATRIX live-object/closure identity rule; no synchronous isolate-thread RPC. Full v1–3 facade/eval proof remains open |
| Keep Preact as a provisional candidate | Smallest candidate passes Refresh/subset functionality, but timing is unstable; first fully passing rule has not selected a final reconciler |
| Keep Store code out of process | Real fatal OOM ends only the helper and preserves a live parent isolate |

**S1 remains OPEN, not P1 approval.** Core sandbox/runtime feasibility and the
signed functional suite pass. Remaining S1 evidence includes a stable reconciler
budget/eval selection, hard external limits during runaway JS allocation, longer
reload-memory attribution, complete activation/global-state semantics and real
cluster bundles/service traces. Production Store globals/permission proxies,
common cage admission (compiler + active + retained), kernel gesture sealing,
atomic native commit validation/paint, final signed app/helper bundles and the
supported-OS matrix remain integration gates. The Store 20-MB result is for a
small synthetic bootstrap, not every Store extension.

S5's **V8 trusted realm + remote DOM remains unimplemented and unvalidated**.
The sandboxed runtime, compiler snapshot, code cache, watchdog and native-tree
adapter are reusable foundations; they do not extract the compatibility kernel,
implement the full DOM bridge or resolve S5's lifecycle/pixel failures. Trusted
v1–3 live synchronous services stay together until complete facades or the fallback
pass. No compatibility exclusion follows from this spike.
