# S3: GLSL compatibility

Phase 0 spike S3 (plan section 11 and the Phase 0 table). Question: can every GLSL
source Powermove renders today run in the engine (wgpu on Metal) through the section 11
pipeline and match WebGL within the parity tolerance, and should step 5 use naga or
SPIRV-Cross?

Code: `engine/spikes/s3-shaders/` (own Cargo workspace, Rust 1.96.1; bun scripts).
Measured on one machine: Apple M4 Max, macOS 27, wgpu 30.0.1 (Metal), naga 30.0.1,
glslang 0.8.1 (`glslang-sys`), spirv-cross2 0.7.1, Chromium 151.0.7922.34 headless
(Playwright) with ANGLE on Metal and on SwiftShader. Dates: 2026-10-11 and 12.

## Answer

- **Compile:** the engine compiles 125 of the 125 programs WebGL links (100%), in every
  source group, on both back ends. It rejects the other 6 exactly as WebGL does. Compile
  parity with WebGL is also 5,000 of 5,000 on fuzz mutants of the corpus (seed 1 without
  Metal, seed 2 through Metal pipeline creation), after two pipeline fixes the fuzz found,
  and again after the coverage-sweep fixes. Corpus mutants cannot reach language
  features the corpus does not use; the coverage sweep below does.
- **Match:** 324 of 326 variants (99.4%) and 124 of 125 WebGL-valid cases (99.2%) are
  within the section 25 tolerance on both back ends. The one failing case is a Store
  effect (`mrsigma/liquid-glass-ios27` 2.0.8) that is ill-conditioned at the pixels
  that differ: WebGL itself moves 99 pixels when its uniforms are scaled by 1 ± 2^-20
  or 1 ± 2^-18, and WebGL on SwiftShader differs from WebGL on Metal at 263 pixels by
  up to 115 CV. No translator setting brought it into tolerance. See "The one
  mismatch".
- **Gate status:** not met as worded ("every ... shader ... matches WebGL"): one Store
  shader of 3 fails in 2 of its 3 variants (`defaults`: 0.117% of pixels over 1 CV
  against the 0.1% allowance and max 99 CV against 4; `viewport`: one pixel at 19 CV).
  Everything else meets it.
- **Beyond the corpus:** a GLSL ES 3.00 coverage sweep (394 rendered probes: every
  built-in overload family, every sampler type, types, operators, control flow,
  qualifiers, preprocessor, reserved identifiers) found that the first version of the
  naga path refused standard programs WebGL draws: `modf`, scalar `normalize`,
  `faceforward`, `reflect`, `refract`, signed `%` as the probes use it (the corpus's
  uses compiled), `-u` on `uint`,
  `texelFetchOffset` (wrong pixels), arrays of `sampler2D`, `uniform mat2`, struct
  uniforms, narrow or array outputs, `gl_FragDepth`, unused unwritten inputs, and user
  names glslang treats as keywords (`texture2D`, `textureGather`). SPIRV-Cross failed
  some of these too. All of those are fixed now. After the fixes, both paths match
  WebGL on 260 of the 270 probes WebGL draws and agree with every WebGL refusal but
  two. The 10 that still differ are open, see "Coverage sweep": 8 programs whose only
  sampler is not a float `sampler2D` (WebGL samples (0, 0, 0, 1), the engine refuses
  them), and 2 where GL leaves the result undefined.
- **Chosen path: naga** (glslang → SPIR-V rewrites → naga IR → `ShaderSource::Naga`).
  SPIRV-Cross matched the same cases and is bit-exact more often, but it hangs on
  WebGL-valid programs (exponential in call-graph paths), needs wgpu's experimental
  unsafe passthrough shaders, and is Metal-only in this form. naga needs more
  pipeline work than SPIRV-Cross (polyfills for seven built-ins, five SPIR-V
  rewrites of its own, see "naga vs SPIRV-Cross"); everything found so far is done,
  except the non-`sampler2D` sampler types listed under "Open naga-path work".

## Pipeline as built

Both paths share steps 0 to 4; they differ at step 5.

0. **Limits** on the author's program (`src/limits.rs`): source size, a budgeted GLSL ES
   preprocessor (macro expansion, statements), WebGL's struct nesting rule, `#extension`
   placement, and WebGL's identifier rules glslang does not check (names containing
   `__`, `webgl_` and `_webgl_` prefixes, `GL_` macro names, `#pragma STDGL
   invariant(all)` in a fragment shader). See "Resource limits".
1. **ES validation** (`compile::validate_es`): glslang's GLSL ES 3.00 front end compiles
   and links the unmodified program with the compositor's vertex shader, as WebGL's
   compile and link would (mandatory fragment precision, uniform precision and type
   matching across stages, unwritten varyings that are used). A program WebGL cannot link
   renders nothing today, so the engine refuses it too. glslang uses WebGL's limits
   (`gl.getParameter` on this machine: 8 draw buffers, 16 texture units, 1,024 uniform
   vectors, texel offsets -8 to 7), which are also the values of the GLSL ES built-in
   constants such as `gl_MaxDrawBuffers`.
2. **Normalize** (`src/normalize.rs`): `#version 300 es` → `#version 450`; precision
   statements and qualifiers removed; identifiers that are keywords or built-ins only in
   GLSL 4.50 or in glslang's Vulkan GLSL (`shared`, `buffer`, `precise`, `fma`,
   `noise1`, `texture2D`, `sampler`, `textureGather`, ...) renamed `pm_*`, also before
   step 1. Line counts never change, so glslang's line numbers are program lines.
3. **glslang** with relaxed Vulkan rules, automatic bindings and locations
   (`src/compile.rs`, driving the C API from `glslang-sys` because relaxed rules must be
   set before parsing). Loose uniforms land in `gl_DefaultUniformBlock`.
4. **SPIR-V rewrites** (`src/rewrite.rs`). Both paths: arrays of `sampler2D` become
   one sampler per element, named `u_extra[k]` as GL names them (GLSL ES 3.00 only
   allows constant indices); distinct bindings for every `sampler2D` (glslang only
   numbers live ones); fragment inputs pinned to the vertex shader's locations by name
   (GL links varyings by name, Metal by location); the fragment interface made what
   WebGL does with it (unused inputs the vertex shader does not write and
   `gl_FragDepth` become private variables; `float`, `vec2`, `vec3`, and array outputs
   are copied to `vec4` outputs padded with 0 at every return from `main`, as ANGLE
   pads them); signed `%` emitted as `OpSRem`, as ANGLE's MSL `%` computes it. naga
   path only: non-finite constants rebuilt at run time; `-u` on `uint` as `0 - u`;
   `texelFetchOffset` as a coordinate add (naga's front end drops the offset);
   `MatrixStride` 8 for `mat2`, `mat3x2`, `mat4x2` uniforms; combined samplers split
   into image plus sampler (globals, function parameters, call sites).
   Then the **SPIR-V limits** (exact types, resolved overloads): private variable size,
   call depth and recursion, active uniform vectors. Then the **bind check**: an active
   named uniform block or a sampler other than a float `sampler2D` is refused, because
   the compositor never binds one (see "Coverage sweep").
5. **Translate.** naga: SPIR-V front end with `adjust_coordinate_space`, the
   derivative-uniformity diagnostic filter set to off, validation, `ShaderSource::Naga`
   (naga's MSL writer runs inside wgpu). On the naga path, step 2 polyfills the
   built-ins naga cannot take: `inverse` and `outerProduct` with ANGLE's formulas
   (naga's MSL writer has neither), `modf` (naga's front end misses its result type),
   and the `float` overloads of `normalize`, `faceforward`, `reflect`, `refract` (naga's
   built-ins take vectors only). SPIRV-Cross: MSL 3.0 with resource indices pinned to
   wgpu-hal's Metal slot assignment, `flip_vertex_y`, variables zero-initialized as
   WebGL initializes them, fed to wgpu as a passthrough shader.
6. **Cache:** not built in the spike. Measured costs are in "Timings"; Metal's own
   pipeline cache already makes repeated builds cheap (warm median 0.20 ms).
7. **Errors** map to the author's lines (`src/errors.rs`): every glslang and limit
   diagnostic is shifted by the number of generated lines before the author's code and
   marked "generated code" when it falls in the preamble. Checked on the corpus: the
   generated type error reports author line 3 where WebGL reports program line 37
   (34 preamble lines); the four broken local drafts report lines 10 and 17.

The renderer (`src/render.rs`) replays each case like the compositor: GL uniform type
rules (`glUniform1f` on an `int` does nothing, a single float leaves a `vec2` at 0 as
`compositor.ts:1024-1030` does, `bool` takes 1f or 1i), the named-then-positional
parameter lookup through active uniforms, unbound units sampling (0, 0, 0, 1),
ping-pong passes reading the previous pass.

**Origin.** The plan's step 2 injects `pm_FragCoord`. The spike instead renders legacy
GLSL in GL row order: images and targets keep row 0 at the bottom, and the vertex output
is flipped (naga's `adjust_coordinate_space`, SPIRV-Cross's `flip_vertex_y`). Then
Metal's `[[position]]` equals GL's `gl_FragCoord` and `dfdy` has WebGL's sign with no
source change, and `texelFetch`, `gl_FragCoord` arithmetic, and derivatives all match
(`glitch-bitwise-hash`, `emboss-dfdy-sign`, `derivative-grid`, and
`ub-texel-fetch-out-of-range` are bit-exact on the naga path; `halftone-fragcoord` has
8-bit difference 0). The flip reverses the winding, so the pipeline's front face is
clockwise; `gl_FrontFacing` is then false for the compositor's quad, as in WebGL.
Consequence for `pm-render`: a
legacy-GLSL node reads and writes textures in GL row order, so the render graph tracks
each texture's row order and folds the flip into the next sampling transform (or blits
once) at the boundary with engine-native nodes. Injecting `pm_FragCoord` instead would
also need `dFdy` negated and `texelFetch` coordinates flipped in user code, which is a
source rewrite the plan forbids in spirit ("never by changing the user's shader").

### The one mismatch

`store/mrsigma-liquid-glass-ios27-2.0.8`, variants `defaults` (naga: 43 pixels over
1 CV, 0.117%, max 99 CV; SPIRV-Cross: 44, max 91) and `viewport` (1 pixel, max 19 and
39). `alt` passes. The older 2.0.1 release of the same effect by another author passes
every variant, as does the local copy.

The shader finds the glass rim with bisection on bilinear alpha against 0.5, keeps the
nearest of 16 rays (`if (distance < best)`), fits a quadratic through `inverse` of a
3×3 moment matrix that can be near singular, and stops on a determinant threshold. All
of these are discontinuous in the last bits of their inputs. The differing pixels are a
12×11 region (x 220 to 231, y 25 to 35) on the rim.

Evidence that the GLSL does not determine these pixels:

- WebGL against itself with every float uniform scaled by 1 + k·2^-20
  (`webgl.ts --perturb k`, k = 1, -1, 4, -4): `defaults` moves 22 pixels at k = 1 (max
  79 CV), 99 pixels across the four directions. 20 of the engine's 43 out-of-tolerance
  pixels fall inside that envelope (`s3-shaders envelope`). The envelope only samples
  input perturbations; the engine's differences come from rounding inside expressions,
  which the uniform perturbation cannot reach.
- WebGL on SwiftShader against WebGL on Metal: 263 pixels over 1 CV, max 115 CV
  (`defaults`); `alt` 118, `viewport` 146. Two conforming WebGL implementations disagree
  by more than the engine does.
- Translator settings tried on the SPIRV-Cross path, with a fresh Metal compile each:
  `#pragma clang fp contract(off)`: 42 pixels (max 69); `contract(fast)`: 44 (91);
  `METAL fp math_mode(safe)`: 39 (99); `math_mode(relaxed)`: 44 (91). Never in
  tolerance. The naga path already uses ANGLE's own `inverse` formulas.

Other corpus shaders are as unstable inside WebGL (`grain` moves 14,384 pixels under
k = 1, `alpha-cutout-discard` 25 pixels at 255 CV, `displace`, `raymarch-sphere`) yet
the engine matches them, because both translations happen to round the same way there.
Across the corpus 317 of 326 variants are stable under k = 1 and 261 of 326 agree
between SwiftShader and Metal WebGL.

What it would take: either reproduce ANGLE's exact MSL for this shader (its expression
order, temporaries, and function forms), which is a different translator, or adopt a
conditioned-parity rule for such shaders (mask pixels where WebGL is unstable under a
fixed set of perturbations and reference implementations, require tolerance on the
rest, and review the sheet). Not decided here; it needs Jude (see Recommendations).

## Coverage sweep

The corpus shows what Powermove shaders use today. The mutant fuzz below starts from
corpus programs, so it never reaches built-ins or types the corpus lacks. An
independent review found three such gaps by hand (`modf`, `sampler2D` arrays,
`isampler2D`). `scripts/coverage.ts` therefore writes one complete program per
GLSL ES 3.00 built-in overload family (section 8 of the specification, each overload
in the family live), per sampler type, and per language feature: types, operators,
control flow, qualifiers, preprocessor, built-in variables and outputs, and 144
identifier probes (most GLSL ES 3.00 reserved words, GLSL 4.50 and Vulkan GLSL
keywords and built-ins, WebGL's reserved prefixes). Each probe renders as a one-pass
effect over the `layer` image, with the compositor's uniforms and `u_tex` on unit 0,
and is compared with WebGL by the same runners as the corpus. `webgl.ts` now records
the GL error a draw raises, so "WebGL links but cannot draw as the compositor binds it"
is its own outcome. Results go through `x / (1 + |x|)`, never `fract`, so rounding
differences stay at rounding size in 8 bits. Inputs stay inside each function's
domain.

**First run** (333 probes, pipeline as of the first report): naga matched 207 of the
244 probes WebGL draws, SPIRV-Cross 222. What it found, by cause (all fixed, see
"Pipeline as built"):

| Finding | Paths | Symptom |
|---|---|---|
| `modf`, all overloads (4 probes) | naga | `MissingSpecialType`: the SPIR-V front end does not register `__modf_result` |
| `normalize`, `faceforward`, `reflect`, `refract` on `float` (4) | naga | `BuiltinArgumentsInvalid`: naga's built-ins take vectors only |
| signed `%` (3) | both | naga lowers `OpSMod` through `floor` and refuses it on integers. SPIRV-Cross computes a true modulo where ANGLE uses `%` (up to 191 CV on negative operands) |
| `-u` on `uint` | naga | `InvalidUnaryOperandType(Negate)` |
| `texelFetchOffset` | naga | offset dropped: 255 CV on 17,396 px |
| arrays of `sampler2D` (4) | both | refused by the sampler split (naga), Metal validation (SPIRV-Cross) |
| `uniform mat2` | naga | `UnsupportedMatrixStride { stride: 16 }` (std140) |
| struct uniform | naga | the reflection sized structs as 16 bytes, so the block was bound too small |
| `out float`, `out vec3`, `out vec4 o[1]` | both / naga | wgpu refuses a narrow output for an RGBA target; naga cannot output arrays |
| `gl_FragDepth` | both | wgpu refuses a depth output without a depth target (WebGL discards it) |
| unused `centroid in` the vertex shader does not write | naga | Metal pipeline: unmatched fragment input |
| `gl_FrontFacing` | both | inverted (the row-order flip reverses winding) |

| `texture2D` as a user name, `#define`, or function; `textureGather` as a user function | both | glslang parses them as Vulkan GLSL keywords or ES built-ins |
| `dvec2`, `a__b`, `webgl_x`, `_webgl_x`, `#pragma STDGL invariant(all)` | both | the engine accepted names WebGL refuses |
| unwritten elements of a private array | SPIRV-Cross | garbage (WebGL zero-initializes every variable) |
| named uniform blocks, non-`sampler2D` samplers | both | render errors or garbage |

What still differs, with cause:

- **8 probes whose only sampler is not a float `sampler2D`**: `sampler3D`, `samplerCube`,
  `sampler2DArray`, `samplerCubeShadow`, `sampler2DArrayShadow`, `isampler3D`,
  `usamplerCube`, `isampler2DArray`. The compositor binds nothing to those targets, so
  WebGL samples an incomplete texture and gets (0, 0, 0, 1). The engine refuses them
  at the bind check. In the other 16 sampler probes WebGL's draw fails
  (`INVALID_OPERATION`): two sampler types share unit 0, which is every effect that
  also reads `u_tex`; or an integer sampler meets the float texture on unit 0
  (`isampler2D`, `usampler2D`, even with `texelFetch` or `textureSize` only); or a
  shadow sampler meets a non-depth texture (`sampler2DShadow`). The engine refuses
  those too, so nothing renders on either side. Declared but unused, these samplers
  are inactive, and both sides render.
- **Ternary on a struct or an array** (2 probes): WebGL refuses (`'?:' : ternary
  operator is not allowed for structures in ESSL 1.0 and webgl`); the engine accepts
  and renders. The rule needs expression types (glslang's AST), like "Expression too
  complex".
- **`out vec3`**: GL leaves the missing alpha undefined. ANGLE writes 0 at most pixels
  and small garbage at 14,298 of 36,864 (up to 0.0078); the engine writes 0. 320 px
  differ by 2 CV.
- **Undefined behavior**: integer division by zero differs on the naga path (naga's
  MSL guards integer division; ANGLE's does not), and an out-of-bounds dynamic array
  read differs on the SPIRV-Cross path. GL defines neither.
- `out ivec4` and active named uniform blocks: WebGL links but fails the draw (float
  target; no buffer bound), and the engine refuses them. Neither side renders.

Limits of the sweep: one probe per overload family over one input range, not every
argument domain or type combination; sampler types only as the compositor binds
units; no WebGL2 shader extensions beyond `GL_OES_standard_derivatives` (others need
`getExtension`, which the compositor never calls); `mediump` and `lowp` run at full
precision on both sides here (ANGLE on Metal), which another GPU may not do.

## Fuzzing and compile parity

`s3-shaders fuzz` runs deterministic mutants (deletions, duplications, swaps, extreme
literals, hostile tokens, splices across programs, byte flips; 1 to 4 stacked per
mutant) of every corpus program, or handwritten resource bombs, in a worker process
with a per-input deadline, attributing crashes and hangs to the back end that was

The two findings, both fixed:

- **Non-finite constants (naga).** `1e39` or `1.0 / 0.0` fold to infinity in glslang
  and ANGLE alike; naga's validator rejects Infinity and NaN literals
  (`ConstExpression { source: Literal(Infinity) }`). 17 WebGL-valid mutants failed. Fix:
  such constants, composites built from them, and initializers that use them are
  rebuilt at run time from the same bits (`OpBitcast` of a `uint` constant) in the
  functions that use them (`materialize_non_finite_constants`). Two generated cases now
  cover it: `nearest-bright-pixel-infinity` is bit-exact, `ray-miss-infinity` has 8-bit
  difference 0.
- **`#extension` after code.** ANGLE refuses `#extension` after any non-preprocessor
  token (GLSL ES 3.00); glslang's ES front end accepts it. Matters for authors: an
  `#extension` line in an effect body comes after the generated preamble, so WebGL
  refuses it today. Fix: the limits preprocessor refuses it with ANGLE's message.

Totals over the 73 probes against WebGL with a draw (classified on the naga path): 62
agree (37 accept, 25 refuse);
4 the engine accepts and WebGL refuses (expression complexity); 4 WebGL links and the
engine refuses (3 macro budgets, plus the two-array program that WebGL then fails to
draw); 3 WebGL did not finish in 90 s and the engine refuses at once. No engine crash or
hang on the naga path. Peak worker memory 758 MB (a 100,000-deep addition chain, which
WebGL refuses). On the SPIRV-Cross path three WebGL-valid call graphs did not finish in
90 s.

Oracle fix (2026-10-12): `webgl-compile.ts --draw` used to bind its render target on
unit 0 as well as attaching it, so a program that sampled a sampler on unit 0 failed
the draw as a feedback loop (`INVALID_OPERATION`) before ANGLE built a pipeline. The
target is now on no unit and unit 0 holds a 1x1 RGBA16F texture, as the compositor
binds `u_tex`. A plain `o = texture(u_tex, v_uv)` now draws without error, and an
`isampler2D` program gets the compositor's real 1282. No limit-probe result changes.
Only probe 71 (the 10^9-iteration loop) samples unit 0, and it is never drawn. The
one draw error, the two-array program, does not sample, and gives 1282 again when
redrawn with the fixed oracle.

Unbounded GPU time is not a translation limit: a 10^9-iteration texture loop links in
WebGL and translates in the engine; drawing it was not attempted (it would stall this
Mac's GPU). The engine needs per-dispatch GPU time limits and device-loss recovery for
it (section 8 and contract 13), not a compile rule.

naga's output is less often bit-identical because it inlines expressions into nested
MSL where SPIRV-Cross keeps SSA temporaries; both stay within 1 CV on every passing
variant. SPIRV-Cross stays useful as a test oracle (a second translation of every
corpus shader) but is not shipped.

cases fail validation, including a direct test with `texture` and `dFdx` inside a
branch on a sampled value. naga 30's validator does not reject these for SPIR-V input,
so the step 5 filter is currently a no-op; it stays, so a future naga that enforces the
rule does not start refusing WebGL-valid shaders.

## The runtime fallback (decision 19)

What S3 says the fallback runner still needs:

- **Trigger.** Nothing in the corpus or the fuzz runs needed it: every WebGL-valid
  corpus program and fuzz mutant translated. That says nothing about the rest of the
  language: on the coverage sweep's first run, 37 WebGL-drawn probes did not match on
  the naga path (refused or different pixels). 8 are still refused at the bind check
  (the non-`sampler2D` samplers WebGL samples as (0, 0, 0, 1)); the fallback would
  render those today. Beyond that it is for failures on a user's machine (a naga or
  Metal compiler version difference, a GPU family with other limits, a program class
  neither the corpus nor the sweep has). The trigger is a failure after the
  WebGL-equivalent checks (ES validation and the WebGL rules of the limits stage) have
  passed: glslang, a SPIR-V rewrite, the bind check, naga, or Metal pipeline creation.
  The engine cannot detect a translated shader that renders differently, so the
  liquid-glass class is not covered by the fallback.
- **Same compile verdict first.** The fallback must not render programs WebGL refuses;
  the engine's ES validation and WebGL rules (struct nesting, call depth, private
  variable size, uniform vectors, `#extension` placement) decide that before
  translation, so a fallback request carries a program known to be WebGL-valid. The
  engine's own budgets (macro expansion, statements) refuse a few programs WebGL
  accepts; those should stay refused rather than fall back, since they are the ones
  that stall WebGL too.
- **The contract in the runner.** One WebGL2 context with the compositor's vertex
  shader, the effect/transition/layer preambles from `kernel/glsl.ts` and
  `extension-layers.ts` (the same generators the engine uses), the uniform replay rules
  above (`setU`/`setI` type rules, positional aliases through active uniforms, unbound
  units), RGBA16F ping-pong targets, linear clamp sampling, inputs and outputs in GL row
  order (no flip on the way in or out, matching the engine's legacy-GLSL nodes).
- **Inputs from the engine.** Per pass: `u_tex`, `u_orig`, `u_backdrop`, `u_from`,
  `u_to` as RGBA16F textures (E-encoded, values above 1.0 kept), plus all uniform
  values for the frame. The upload back is RGBA16F at composition size, like the
  `raster` override.
- **Hang and crash safety.** ANGLE stalled for 8 s on a 2^24 macro bomb and the next
  program found the context lost; it did not draw a 512 KiB program within 90 s, and a
  WebGL-valid program with two 62.5 KiB arrays fails at draw. The runner's compile must be
  asynchronous (`KHR_parallel_shader_compile`), bounded by a deadline, and survive
  context loss by recreating the context and marking the definition failed.
- **Reporting.** Marked not headless-renderable (decision 19), with the stage and
  message of the translation failure so the pipeline gets fixed (section 11: "a failure
  is fixed in the pipeline").

## Open naga-path work

Done in this spike (from the corpus, the fuzz, and the coverage sweep): the seven
polyfills, the sampler split and sampler arrays, non-finite constants, `uint`
negation, `texelFetchOffset`, 2-row matrix strides, the fragment interface rewrites,
signed remainder. Still open:

- **Non-`sampler2D` samplers** (`sampler3D`, `samplerCube`, `sampler2DArray`, shadow
  and integer samplers). Matching WebGL needs the compositor's binding model in the
  engine: a texture unit per sampler with one binding per target, constant (0, 0, 0, 1)
  dummy textures of the right dimension and sample type for empty targets, and WebGL's
  draw-time rules (two sampler types on one unit, an integer sampler on a float
  texture, a shadow sampler on a non-depth texture: nothing renders). On the naga path
  integer sampling also needs a rewrite: naga refuses `texture()` on integer images
  (`InvalidImageClass`); with the compositor's linear filtering an integer texture is
  always incomplete, so the lowering is a fetch that returns the dummy. Today the
  engine refuses all of these at the bind check: correct for the 16 probes WebGL cannot
  draw, wrong for the 8 it draws.
- **WebGL rules that need expression types:** ternary operators on structs and arrays,
  "Expression too complex". Both make the engine accept programs WebGL refuses.
- Everything outside the sweep: it has one probe per overload family. Argument domains
  near edge cases, combinations of features, and GLSL ES 3.00 grammar corners not
  listed in "Coverage sweep" are not covered. The sweep and its first-run findings
  are the reason to keep running it, not proof of completeness.

## Gaps

- GLSL ES coverage is measured by the sweep, not proven: see "Open naga-path work".
  The mutant fuzz only recombines corpus programs; it did not find any of the
  first-run sweep failures.
- Test inputs are in [0, 1], so the contract rule that E-encoded values above 1.0
  pass through legacy GLSL is not exercised. Neither are `clamp: true` effects (a new
  engine flag applied outside the shader) or `viewportPadding` (a compositor viewport
  rule outside the shader). The comparison also clamps to [0, 1] before quantizing to
  8 bits, so an above-1.0 input variant needs a float-domain comparison too.
- The generated corpus was not produced through the in-app agent harness (see
  Corpus). The Store has only 3 public extensions.
- One machine, one GPU family (M4 Max). Other Apple GPU families, Intel Macs, and other
  wgpu back ends are not measured; the 1024 uniform-vector limit is what WebGL reports
  here.
- WebGL's "Expression too complex" rule (AST depth 256) is not reproduced: the engine
  accepts programs WebGL refuses for it (4 probes; none in the corpus or the fuzz runs).
  Reproducing it needs a GLSL AST (glslang's C++ API or a parser) and ANGLE's exact
  counting, including its swizzle folding.
- The collector evaluates Store and local extension modules in `node:vm` to capture
  their registrations. That is not a security boundary; it was acceptable for 3
  gatekept public releases on a development machine, but a CI version should run the
  collector in the app's extension sandbox.
- Translation cache (step 6) not built; cold-compile numbers are in Timings.
- Local forks of built-ins: none on this Mac (the local extensions folder holds a copy of
  a Store extension and a non-GLSL layer).
- three.js shader programs are S7's corpus, not covered here.

## Recommendations

1. **Adopt the naga path** for `pm-render` with this spike's pipeline: the limits
   stage, the polyfills, and the SPIR-V rewrites in "Pipeline as built" (sampler split
   and arrays, varyings by name, fragment interface, signed remainder, non-finite
   constants, `uint` negation, `texelFetchOffset`, 2-row matrix strides), plus the bind
   check. Keep SPIRV-Cross only as a test-time second opinion. Before relying on it for
   arbitrary Store and agent GLSL, close the open naga-path work (non-`sampler2D`
   samplers) or route the bind-check refusals to the decision 19 fallback.
2. **Run the coverage sweep as a regression suite** with the corpus, and grow it
   whenever a user shader fails: its first run found 37 failures that neither the
   corpus nor 5,000 fuzz mutants had reached.
3. **Decide the ill-conditioned class with Jude.** The liquid-glass mismatch cannot be
   closed by a translator other than ANGLE itself. Options: accept it on the evidence
   above as a reviewed exception; or add a parity class "WebGL-unstable pixels" (mask
   pixels where WebGL moves under perturbation or between ANGLE back ends, require the
   tolerance elsewhere, attach a reviewed sheet). The gate wording ("every ... shader
   matches") then needs that class named in section 25.
4. **Run translation in a helper process** with a deadline (the plan's "resource-limited"):
   the limits here stop every bomb found, but glslang and the Metal compiler are
   third-party native code; a crash or hang must cost one definition, not the engine.
   Translate and create pipelines on a thread with a large stack (1 GiB reserved here).
5. **Keep the limits stage and its probes as a regression suite**, and rerun the WebGL
   oracle when Chromium or naga changes: these limits are WebGL's, measured, and will
   drift.
6. **Render GLSL nodes in GL row order** and let the render graph track row order per
   texture (see Origin), instead of injecting `pm_FragCoord`.
7. **Before cutover:** run the generated prompts through the in-app agent harness and
   add the outputs; rerun on the other reference machines; build the step 6 cache; add
   GPU-time limits for runaway loops; reproduce "Expression too complex" if exact
   compile parity is wanted.
