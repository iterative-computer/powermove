# S5: WASM evaluator

Spike S5 from plan section 26, Phase 0. Lane: Model and evaluation. It informs
Phase 1 and is one of the Phase 1 gates.

**Pass criteria (plan):** `evP` under 1 µs for cached values. Patch apply under
0.2 ms for property edits and under 2 ms for structural edits on 884 layers. A
per-window memory budget. Also checked here: native and WASM results are
bit-identical with `libm` (section 2, determinism), and structural edits
invalidate only the changed ids (section 6).

**Result: pass**, measured in a sandboxed, context-isolated Electron 44
renderer under the editor CSP plus `'wasm-unsafe-eval'`, and in Node. Every
target passes in all 10 Electron runs. There is one design condition: a
structural patch must reach the mirror as an id-keyed order patch or as UTF-8
bytes the renderer already has. Running `JSON.stringify` on the whole
884-layer array costs 2.1 ms by itself in the renderer, so that path fails the
2 ms target before the mirror does any work. Node passes every target in its
median run. Its worst runs under heavy machine load are listed under Node
below.

Code: `engine/spikes/s5-wasm/` (its own Cargo workspace). Reproduce with
`engine/spikes/s5-wasm/scripts/run-all.sh [rounds]`.

## What was built

- **`s5-core`**: a minimal Rust mirror of one composition document.
  - **Layers**: id, type, `from`, `parent`, `group`, and every transform
    channel (`p`).
  - **Keyframes**: the speed and influence ease model, ported from
    `core/anim/temporal-ease.ts` and `legacy/core/temporal-bridge.ts`. The
    port covers linear, bezier, and hold segments; auto-bezier refresh;
    influence clamping; and `solveCurveParam` with the same constants. Every
    expression keeps the TypeScript operation order (no FMA, no
    reassociation).
  - **`PM.ev`, `PM.localMatrix`, `PM.transformParentMatrix`,
    `PM.worldMatrix`**: groups and parenting work as in
    `legacy/core/layer-groups.ts` and `anim.ts`.
  - **Leaf patches** (`shared/patch.ts` semantics): a missing parent skips the
    patch, deleting an array index splices, and an index past the end leaves
    holes.
  - **Id-keyed reconciliation** of the `layers` array, in two forms:
    - a whole-array set; and
    - an order patch: the new order as ids plus the JSON of only the changed
      or new layers.

    An element whose bytes equal the stored bytes for its id is kept without
    parsing. Only changed, new, and removed ids invalidate cached answers.
    Within a changed layer, only handles whose channel or `from` actually
    changed are invalidated.
  - **Fields the evaluator never reads** (the edit log, assets) stay as
    validated raw bytes.
  - **Transcendental functions** (`sin`, `cos`, `tan`) come from the `libm`
    crate on every target. A `system-math` feature switches to platform math,
    but only as the negative control for the bit-identity check.
- **`s5-wasm`**: wasm-bindgen exports (CLI pinned to 0.2.129) for the JS fast
  path:
  - numeric ids interned per (layer id, channel). `ev(id, t)` takes two
    numbers and returns one, with no strings crossing the boundary;
  - batch results written into a shared `Float64Array` view of linear memory.
    Ids are read from a `Uint32Array` view, and patches are written through a
    `Uint8Array` view;
  - grow-only buffers. The JS side (`js/evaluator.mjs`) re-acquires every
    view when `memory.buffer` changes after growth or when a buffer moves;
  - `evP(L, prop, T, key)` keeps the kernel's live-object signature through
    an identity registry (a `WeakMap` from the live property object to its
    id);
  - writes queue and are flushed before the next query (section 6);
  - a counting global allocator, so memory reports the live Rust heap, not
    only the size of linear memory.

  The module is 322,498 bytes.
- **`s5-native`**: produces the native vectors for the bit-identity check,
  compares vector files bitwise, and runs native reference timings.
- **`js/synth.mjs`**: a deterministic synthetic project shaped like the
  884-layer project.
  - **Shape**: 884 layers (39 groups up to 3 deep, 706 shapes, 131 text
    layers, 2 solids, 3 nulls, 3 audio layers) and 15,858 transform channels.
    66 channels are animated, with 143 keys.
  - **Effects and edit log**: 213 effect parameters, and a 509-entry edit log
    of 260 KB.
  - **Size**: 1.40 MB of JSON, with a median layer of 1.2 KB.

  Only aggregate counts are reproduced; every name, value, and id is
  generated. A second, smaller project (`coverageProject`) stresses dense
  keys, holds, auto and continuous bezier, extreme speeds and influences,
  rotations up to 10⁵ degrees, 89.9° skew, and parent chains.
- **Electron harness** (`electron/main.cjs`) for Electron 44.0.0 (Chrome
  152.0.7977.54) from `apps/desktop/node_modules`.
  - **Window**: hidden, offscreen, non-focusable, no Dock icon. Its
    `webPreferences` are `sandbox: true`, `contextIsolation: true`,
    `nodeIntegration: false`, and there is no preload.
  - **Pages**: served from a custom standard scheme, with the editor's CSP
    from `main/security-policy.ts` and the plan's single change
    (`script-src 'self' 'wasm-unsafe-eval'`).
  - **Modes**:
    - `plain` is the configuration S5 is judged in;
    - `isolated` adds COOP and COEP only to get 5 µs timers instead of
      100 µs;
    - `nowasm` uses today's CSP as the negative control.
  - **Process priority**: the hidden renderer is kept at foreground priority
    (`disable-renderer-backgrounding`), as a visible editor window would be.

### Correctness

These checks passed on every host and in every run:

- After 540 timed structural edits (plus their setup and cleanup patches)
  and 7,800 property and key edits, the patched mirror serializes to exactly
  the renderer's own document.
- The patched mirror's answers equal those of a mirror freshly loaded from
  that document: 105,810 values (channels and world matrices at 5 times),
  with 0 differing.
- No edit returned a wrong value. Every `position.x` edit on a static
  channel reads back the new value, and after each of 3,000 keyframe value
  edits the channel answers the new value at that key's time.
- When linear memory grows from 16.8 MB to 42.0 MB through `memory.grow`,
  every view is re-acquired and batch results are unchanged.
- `cargo test`: 11 integration tests plus unit tests (ease, patch semantics,
  framing, JSON scanning, byte comparison). They cover:
  - reorder, insert, and delete invalidation;
  - property, keyframe, and `from` edits;
  - id changes and element deletes;
  - duplicate ids resolving to the first;
  - order patches;
  - shadow replay against a `serde_json::Value` model;
  - group and parent matrices;
  - malformed input returning an error, not a panic.

  `cargo clippy --all-targets` is clean.
- Out-of-scope properties are reported and answer `NaN`, never a guess: 0 in
  both synthetic projects.

### Native vs WASM bit identity (`libm`)

| Project | Values | Native (libm) vs WASM in Node | vs WASM in Electron (plain, isolated; 10 runs each) | Negative control (platform math) |
|---|---|---|---|---|
| 884-layer | 2,560,602 (15,858 channels + 884 × 6 matrix values, × 121 times) | identical | identical (SHA-256 `017413b6…`) | 7,816 differ |
| Coverage | 177,144 | identical | identical (SHA-256 `4aea5411…`) | 8,144 differ |

The 121 times include frame-aligned, off-frame, negative, and past-the-end
values. The negative control builds the same code against Apple's libm and
shows the check can fail. **Pass.**

The legacy TypeScript evaluator (`legacy/core/anim.ts`,
`temporal-bridge.ts`, `layer-groups.ts`, unmodified, run in V8) is compared on
the same inputs:

- **Channel values**: all bit-identical.
- **World matrices**: 2,541 of 2,560,602 values differ, by at most 2 ulps. In
  the coverage project, 272 differ by at most 32 ulps, where `tan(89.9°)`
  amplifies the difference.
- **Cause**: V8's `Math.sin`, `Math.cos`, and `Math.tan` versus `libm`.
- **Tolerance**: all differences are far inside section 25's evaluation
  tolerance (1e-9 + 1e-9·|b|).

Bit identity with the legacy evaluator is not an S5 criterion; the comparison
shows the port reproduces the arithmetic exactly.

### Security configuration

These checks held in every run:

- **CSP with `'wasm-unsafe-eval'`**: the module compiles and instantiates

- **String eval**: `new Function` stays blocked with an `EvalError`.
- **Today's CSP** (the `nowasm` control): wasm fails with a CSP

## Per-window memory budget

The plan asks for a per-window budget including 3D meshes and BVHs (section
19) but sets no number. S5 measures the 2D mirror and proposes the 2D part of
the budget. The 3D part is outside this spike (S7 and Phase 3a).

The Rust heap figures come from the counting allocator, the renderer
footprint from `footprint -p` (physical footprint), and the other figures from
`memory.buffer` and the bench's own accounting.

| Measurement, 884-layer project | Value |
|---|---|
| Rust heap live, steady state (load buffer released, all 15,858 handles interned and cached, world matrices computed) | 4.74 MB |
| Of which raw layer JSON | 1.14 MB |
| Rust heap peak during load | 3.97 MB, plus the 1.40 MB input buffer |
| Linear memory, steady state | 6.62 MB |
| Linear memory, high water after the whole benchmark (two mirrors alive at once, 1.1 MB patch buffers) | 16.78 MB |
| Rust heap after the benchmark | 8.10 MB = 4.74 steady + 2.28 input-buffer capacity + 1.04 for 6,480 handles of deleted layers (160 bytes each) + the grown edit log |
| Renderer physical footprint: page loaded → wasm instantiated → project loaded | 18.3 → 20.3 → 37.7 MB (median of 10). The +9 MB at load includes the JS-side project and its 1.4 MB JSON string |
| Renderer RSS: page loaded → wasm instantiated → project loaded | 88.4 → 91.8 → 118.7 MB |

**Proposed 2D budget for `pm-wasm`**, per window, for a document of this
size:

- **Live Rust heap**: at most 8 MB, about 4× the raw layer JSON plus handles.
- **Linear memory high water**: at most 32 MB.

Measured: 4.74 MB live heap and 16.8 MB high water under a benchmark harsher
than editing. **Pass** against the proposal. The integration lane and Jude
should confirm the number when the 3D share is measured.

## Findings for Phase 1

1. **Do not stringify the whole layers array for structural edits.** Use
   id-keyed order patches (changed layers only) or the bytes the history
   already produces.
   - Today `scopedPatches` (`legacy/core/history.ts:109-127`) stringifies
     `{path, ...after}` for each scope and UTF-8-encodes it, but only to count
     bytes; then it drops the bytes.
   - Phase 1 should keep that encoding and hand it to the mirror. That needs
     a frame kind that accepts the whole patch object rather than the bare
     value. The spike measured the bare value, so the patch-object frame is
     not built yet.
   - The history's own stringify (2 to 4 ms per structural commit on 884
     layers) is an existing cost that the mirror does not add to.
2. **Release handles.** Interned handles live as long as the mirror, at about
   160 bytes each. Phase 1 needs a release path: when a layer is deleted from
   the document and no registry entry refers to it, or through a
   `FinalizationRegistry` on the identity registry's live objects.
3. **Linear memory never shrinks.** A whole-project load sets the high water
   mark: input buffer plus parse, about 4 MB above steady state here. Patch
   buffers keep the capacity of the largest structural patch. Phase 1 should
   load in chunks or by streaming, and cap retained buffer capacity.
4. **World matrices cost 220 to 290 µs per frame for 884 layers in wasm**
   (204 µs native), with group-chain matrices recomputed per layer. This is
   not an S5 target, but Phase 1 should cache group and parent matrices per
   evaluation pass before the layer-drag gates in sections 25 and 3a.
5. **Cached `evP` is about 25 ns**, roughly 40 times under target. Of that,
   about 15 ns is the JS-to-wasm call and the rest is the `WeakMap` identity
   lookup. A batch API is 2 ns per value. Synchronous answers through the
   boundary have room for the expression and 3D work Phase 1 adds.

## Scope and limits

- **Mirrored**: transform channels and numeric keyframes with speed and
  influence ease, groups and parenting, and leaf and structural patches for
  the layers array.
- **Excluded by the brief**: expressions, springs, discrete values (text,
  color, booleans), keys saved before the speed and influence model
  (`eo`/`ei` handles, converted by `adoptTemporalEase`), 3D, effects, masks,
  and nested compositions. They are reported and answer `NaN`.
- **Synthetic project only**: the project reproduces the 884-layer project's
  aggregate structure, not its content. The real project was not used (it
  stays outside the repository).
- **Reference machine**: measured only on Jude's M4 Max (decision 11). The
  base-machine gates are deferred and **unverified**.
- **Shared machine**: other lanes were running during every measurement, at a
  load average of 16 to 21 in the final session. Numbers on a quiet machine
  should be equal or better.
- **Renderer priority**: the hidden renderer ran with backgrounding disabled,
  as a visible window would. The backgrounded case
  (`S5_ALLOW_BACKGROUNDING=1`) was not measured in the final session.
- **Harness note**: under the agent's macOS sandbox, a second renderer
  process in the same Electron instance failed its Mach port rendezvous. The
  runner therefore starts one Electron process per mode. This affects only the
  harness, not the product.

## Reproducing

```sh
source engine/env.sh                 # pinned Rust 1.96.1
bun install                          # Electron 44 in apps/desktop/node_modules
engine/spikes/s5-wasm/scripts/run-all.sh 10
```

- `run-all.sh` builds the wasm module, the bindings, and the native runner. It
  then runs N rounds of Node and Electron (all three modes), the native-versus-
  wasm vector comparison with its negative control, the legacy parity check,
  and the summary (`js/summarize.mjs`).
- Raw results stay in `engine/spikes/s5-wasm/results/` (gitignored).
- `cargo test --release` and `cargo clippy --release --all-targets` run in
  `engine/spikes/s5-wasm/`.
